# Test Cases: JwtAuthProvider

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-Login-Request | Integración | `login()` realiza POST al endpoint correcto con `withCredentials=true` | `API_BASE_URL` configurado, credenciales válidas | 1. Llamar `login({email, password})`. 2. Verificar petición HTTP emitida. | POST a `{API_BASE_URL}/auth/login` con las credenciales en el body y `withCredentials: true`. Retorna `TokenResponse`. | Valida la integración HTTP base del provider; `withCredentials` es crítico para que la cookie httpOnly sea configurada por el servidor. |
| TC-Logout-Request | Integración | `logout()` realiza POST al endpoint correcto con `withCredentials=true` | Usuario autenticado | 1. Llamar `logout()`. 2. Verificar petición HTTP emitida. | POST a `{API_BASE_URL}/auth/logout` con `withCredentials: true`. | Asegura que la cookie de refresh token del servidor se invalida correctamente al hacer logout. |
| TC-RefreshToken-Request | Integración | `refreshAccessToken()` usa solo la cookie httpOnly (sin body) | Cookie de refresh token presente en el navegador | 1. Llamar `refreshAccessToken()`. 2. Verificar petición HTTP emitida. | POST a `{API_BASE_URL}/auth/refresh` con `withCredentials: true` y sin token en el body. Retorna nuevo `TokenResponse`. | Verifica el flujo seguro de renovación de tokens basado en cookies httpOnly, que no expone el refresh token en JavaScript. |
| TC-GetUser-Request | Integración | `getUser()` envía el token de acceso en el header `Authorization` | Access token válido disponible | 1. Llamar `getUser('valid-token')`. 2. Verificar petición HTTP emitida. | GET a `{API_BASE_URL}/auth/me` con header `Authorization: Bearer valid-token`. Retorna `AuthUser`. | Confirma que el endpoint de perfil de usuario recibe el token correcto para identificar al usuario en el servidor. |
| TC-IsTokenExpired-Active | Componente | Token activo no es considerado expirado dentro del umbral | Token con `accessTokenExpiresAt` en 5 minutos | 1. Llamar `isTokenExpired(session)` con `expiresAt = Date.now() + 300_000`. | Retorna `false`. | Previene refreshes prematuros innecesarios que podrían interrumpir el flujo del usuario. |
| TC-IsTokenExpired-AtThreshold | Componente | Token dentro del umbral de renovación es considerado expirado | Token con `accessTokenExpiresAt` a 30 segundos del vencimiento (umbral = 60s) | 1. Llamar `isTokenExpired(session)` con `expiresAt = Date.now() + 30_000`. | Retorna `true` (30s < 60s threshold). | Garantiza que el token se renueva proactivamente antes de expirar, evitando llamadas fallidas a la API. |
