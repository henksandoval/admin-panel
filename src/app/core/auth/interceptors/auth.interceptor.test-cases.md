# Test Cases: AuthInterceptor

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-TokenInjection | Integración | Añade el header `Authorization: Bearer` a peticiones privadas | `authService.accessToken` = `'valid-token'` | 1. Realizar una petición HTTP a una URL no pública. | La petición sale con el header `Authorization: Bearer valid-token`. | Garantiza que todas las APIs protegidas reciben el token; sin esto, todas las peticiones autenticadas fallan con 401. |
| TC-PublicUrlSkip | Integración | No añade token a URLs públicas configuradas | URL de la petición está en `AUTH_PUBLIC_URLS` (ej. `/auth/login`) | 1. Realizar una petición a `/auth/login`. | La petición sale sin el header `Authorization`. | Evita enviar tokens en endpoints públicos (login, refresh) que no lo necesitan y podrían causar bucles. |
| TC-401Refresh-AndRetry | Integración | Al recibir 401, refresca el token y reintenta la petición original | Token expirado, provider retorna nuevo `TokenResponse` exitosamente | 1. Realizar petición HTTP. 2. Servidor responde 401. 3. `refreshAccessToken` retorna nuevo token. 4. Petición original es reintentada. | La petición original se reintenta con el nuevo token y completa exitosamente. | Core del manejo transparente de tokens; sin esto, el usuario recibiría errores 401 en vez de una experiencia fluida. |
| TC-401RefreshFailure-Logout | Integración | Fallo en el refresh tras un 401 limpia la sesión y propaga el error | Token expirado, `refreshAccessToken` lanza un error | 1. Realizar petición HTTP. 2. Servidor responde 401. 3. `refreshAccessToken` falla. | `authService.logout()` es llamado; el error se propaga al subscriber original. | Previene que el usuario quede en un estado autenticado inválido cuando el refresh token también ha expirado. |
| TC-401ConcurrentQueue | Integración | Peticiones concurrentes que reciben 401 son encoladas y reintentadas con el nuevo token | Múltiples peticiones en vuelo simultáneamente, token expirado | 1. Enviar 3 peticiones simultáneas. 2. Las 3 reciben 401. 3. Solo se lanza un `refreshAccessToken`. 4. Las 3 peticiones se reintentan con el nuevo token. | `refreshAccessToken` se llama exactamente una vez; las 3 peticiones completan exitosamente con el nuevo token. | Previene el race condition donde múltiples refreshes simultáneos invalidan el token entre sí, causando logout forzado. |
