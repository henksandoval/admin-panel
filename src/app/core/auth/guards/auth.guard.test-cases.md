# Test Cases: Auth Guards

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-AuthGuard-Authenticated | Integración | Permite el acceso a rutas protegidas cuando el usuario está autenticado | `authService.status` = `'authenticated'` | 1. Ejecutar `authGuard` sobre una ruta protegida. | Guard retorna `true`, la navegación procede. | Happy path del guard; sin esto, ningún usuario autenticado podría acceder a las rutas protegidas. |
| TC-AuthGuard-Unauthenticated | Integración | Redirige al login con `returnUrl` cuando el usuario no está autenticado | `authService.status` = `'unauthenticated'` | 1. Ejecutar `authGuard` sobre `/dashboard`. | Guard retorna un `UrlTree` apuntando a `AUTH_DEFAULTS.loginRoute` con `queryParam returnUrl='/dashboard'`. | Protege las rutas privadas y preserva el contexto del usuario para redirigirle tras el login. |
| TC-AuthGuard-WaitsForChecking | Integración | El guard espera a que la comprobación de sesión inicial termine antes de decidir | `authService.status` comienza en `'checking'` | 1. Ejecutar `authGuard`. 2. Status emite `'checking'`. 3. Status emite `'authenticated'`. | El guard no resuelve durante el estado `'checking'`; resuelve con `true` cuando llega `'authenticated'`. | Evita el race condition donde el guard redirige al login antes de que `checkSession()` haya terminado. |
| TC-RoleGuard-AnyRole-Granted | Integración | Permite acceso cuando el usuario tiene al menos uno de los roles requeridos | Usuario con roles `['editor']`, ruta requiere `['admin', 'editor']` con `requireAll=false` | 1. Ejecutar `roleGuard` con `route.data = { roles: ['admin', 'editor'], requireAll: false }`. | Guard retorna `true`. | Valida la lógica OR del control de acceso, el caso más común en sistemas con múltiples roles. |
| TC-RoleGuard-AllRoles-Granted | Integración | Permite acceso cuando el usuario tiene todos los roles requeridos (AND logic) | Usuario con roles `['admin', 'editor']`, ruta requiere ambos con `requireAll=true` | 1. Ejecutar `roleGuard` con `route.data = { roles: ['admin', 'editor'], requireAll: true }`. | Guard retorna `true`. | Valida la lógica AND para rutas que requieren múltiples roles simultáneamente (ej. auditoría). |
| TC-RoleGuard-AllRoles-Denied | Integración | Redirige a 403 cuando el usuario no tiene todos los roles requeridos (AND logic) | Usuario con roles `['editor']`, ruta requiere `['admin', 'editor']` con `requireAll=true` | 1. Ejecutar `roleGuard` con `route.data = { roles: ['admin', 'editor'], requireAll: true }`. | Guard retorna un `UrlTree` apuntando a `AUTH_DEFAULTS.unauthorizedRoute` (403). | Previene acceso parcial en rutas que necesitan una combinación completa de roles. |
| TC-RoleGuard-NoMatchingRole | Integración | Redirige a 403 cuando el usuario no tiene ninguno de los roles requeridos | Usuario con roles `['viewer']`, ruta requiere `['admin']` | 1. Ejecutar `roleGuard` con `route.data = { roles: ['admin'] }`. | Guard retorna un `UrlTree` apuntando a `/errors/403`. | Verifica que usuarios con perfiles de bajo privilegio son bloqueados correctamente. |
| TC-RoleGuard-NoUser | Integración | Retorna `true` cuando no hay usuario (authGuard ya gestiona la autenticación) | `authService.currentUser` = `null` | 1. Ejecutar `roleGuard` con roles configurados en la ruta. | Guard retorna `true` y delega la responsabilidad a `authGuard`. | Evita responsabilidad duplicada entre guards; si hay doble bloqueo, la UX se vuelve impredecible. |
