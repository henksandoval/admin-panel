# Test Cases: InitializationService

| ID del Test                        | Tipo        | Escenario / Propósito                                                                 | Precondiciones                                     | Pasos clave                                                                                                                                                   | Resultado Esperado                                                                                        | Justificación de Valor                                                                                               |
|------------------------------------|-------------|---------------------------------------------------------------------------------------|----------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------|
| TC-Init-FullSequence               | Integración | La secuencia de inicialización completa configura rutas dinámicas correctamente       | Session check, menu load y route build exitosos    | 1. Llamar `initialize()`. 2. `checkSession()` completa. 3. `loadMenu()` retorna ítems. 4. `buildRoutes()` genera rutas. 5. `router.resetConfig()` es llamado. | `router.resetConfig` recibe las rutas dinámicas combinadas con `AUTH_ROUTES` y el layout con `authGuard`. | Valida el contrato de startup de la app; si falla, los usuarios navegan a rutas vacías o no protegidas.              |
| TC-Init-NoSession-ContinuesLoading | Integración | Si no hay sesión previa, la carga del menú y las rutas continúan igualmente           | `checkSession()` completa vacío (sin token previo) | 1. Llamar `initialize()`. 2. `checkSession()` emite EMPTY (sin sesión). 3. `loadMenu()` es llamado de todas formas.                                           | `loadMenu()` es invocado y las rutas se configuran correctamente.                                         | El startup no debe depender de que haya sesión activa; el menú y las rutas públicas deben estar siempre disponibles. |
| TC-Init-MenuLoadFailure            | Integración | Error al cargar el menú lanza la excepción para que el proceso de bootstrap la maneje | `loadMenu()` falla con un error HTTP               | 1. Llamar `initialize()`. 2. `checkSession()` completa. 3. `loadMenu()` lanza error.                                                                          | El error es registrado por el logger y relanzado. `router.resetConfig` **no** es llamado.                 | Previene que la app arranque con rutas incompletas o en estado inconsistente cuando el backend no está disponible.   |
