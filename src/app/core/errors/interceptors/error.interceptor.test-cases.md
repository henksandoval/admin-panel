# Test Cases: ErrorInterceptor

| ID del Test                        | Tipo        | Escenario / Propósito                                                                          | Precondiciones                                                  | Pasos clave                                                                  | Resultado Esperado                                                                                              | Justificación de Valor                                                                                                             |
|------------------------------------|-------------|------------------------------------------------------------------------------------------------|-----------------------------------------------------------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| NavigationHandled-NoNotification   | Integración | Errores con página dedicada (403, 404, 500, 503) no muestran toast                             | Servidor responde con status 403, 404, 500 o 503                | 1. Realizar petición HTTP. 2. Servidor responde con uno de estos status.     | El router navega a la página de error correspondiente. `NotificationService` NO es llamado.                     | La página de error ya comunica el problema al usuario; un toast adicional sería ruido innecesario.                                 |
| NetworkError-WarningNotification   | Integración | Errores de red muestran un toast de advertencia                                                | La petición falla con un `ProgressEvent` (error de red)         | 1. Realizar petición HTTP. 2. La petición falla con error de red.            | `NotificationService.warning()` es llamado. `NotificationService.error()` NO es llamado.                        | Diferencia entre errores de conectividad y errores del servidor; el usuario debe saber si el problema es local.                    |
| ClientError-WarningNotification    | Integración | Errores 4xx sin página dedicada (400, 422, etc.) muestran un toast de advertencia              | Servidor responde con un status 4xx sin redirección configurada | 1. Realizar petición HTTP. 2. Servidor responde con error 400.               | `NotificationService.warning()` es llamado. `NotificationService.error()` NO es llamado.                        | Son errores esperados del flujo normal; la advertencia es suficiente sin alarmar al usuario.                                       |
| OperationalError-ErrorNotification | Integración | Errores 5xx sin página dedicada (502, 504, etc.) muestran un toast de error con mayor duración | Servidor responde con un status 5xx sin redirección configurada | 1. Realizar petición HTTP. 2. Servidor responde con error 502.               | `NotificationService.error()` es llamado con duración de 8000ms. `NotificationService.warning()` NO es llamado. | Son errores operativos graves que requieren mayor visibilidad; la duración extendida garantiza que el usuario vea la notificación. |
| ErrorPropagation                   | Integración | El error HTTP siempre se propaga al componente tras el manejo                                  | Cualquier error HTTP                                            | 1. Suscribirse al observable de la petición. 2. Servidor responde con error. | El subscriber del observable recibe el error; el interceptor no lo absorbe silenciosamente.                     | Previene que los componentes pierdan la capacidad de manejar errores específicos (ej. reintentar en 503).                          |
