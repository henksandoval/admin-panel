# Test Cases: RegisterComponent

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-RegisterHappyPath | E2E | Registro exitoso con datos válidos navega a la página de login | Usuario en `/auth/register` | 1. Rellenar nombre, email, contraseña y confirmación con datos válidos. 2. Hacer clic en "Create account". 3. Esperar la respuesta | El usuario es redirigido a `/auth/login` | Es el flujo crítico de alta; su fallo impide la incorporación de nuevos usuarios |
| TC-RegisterPasswordMismatch | Componente | El validador de grupo muestra error si las contraseñas no coinciden | Componente renderizado con `passwordMatchValidator` activo | 1. Introducir contraseña válida. 2. Introducir una confirmación diferente. 3. Intentar enviar el formulario. | El formulario es inválido; el control `confirm` muestra el error `passwordMismatch`; `authService.register` no es invocado | El validador cruzado es lógica custom no nativa del navegador; sin este test el bug puede pasar a producción silenciosamente |
| TC-RegisterApiError | Integración | Un error de la API muestra el mensaje de error al usuario | `authService.register` retorna `throwError(() => new Error('Email already in use'))` | 1. Enviar formulario con datos válidos. 2. El servicio rechaza la petición. | El bloque de error es visible con el mensaje recibido; `status` es `'error'`; no hay navegación | Garantiza que errores como email duplicado no se pierden silenciosamente |
| TC-RegisterLoadingState | Componente | Durante el registro el botón queda deshabilitado y no se pueden enviar dobles | `authService.register` retorna un Observable que no completa inmediatamente | 1. Enviar formulario válido. 2. Verificar estado del botón antes de que complete. | `isLoading()` es `true`; el botón está `disabled`; una segunda llamada a `onSubmit()` es ignorada | Evita registros duplicados por doble clic |
| TC-RegisterShowPasswordToggle | Componente | El checkbox "Show password" cambia el tipo de ambos campos de contraseña simultáneamente | Componente renderizado | 1. Verificar que ambos campos tienen `type="password"`. 2. Activar el checkbox "Show password". | Ambos campos `password` y `confirm` cambian a `type="text"` al mismo tiempo | Valida que `showPassword` signal controla ambas computed `passwordFieldConfig` y `confirmFieldConfig` correctamente |
