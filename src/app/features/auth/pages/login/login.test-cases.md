# Test Cases: LoginComponent

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-LoginHappyPath | E2E | Login exitoso con credenciales válidas redirige al usuario | Usuario no autenticado en `/auth/login` | 1. Introducir email y contraseña válidos. 2. Hacer clic en "Sign In". 3. Esperar la respuesta del servidor | El usuario es redirigido a la ruta protegida (o `returnUrl` si existe) | Es el flujo de negocio principal; su fallo bloquea el acceso a toda la aplicación |
| TC-LoginInvalidFormBlocked | Componente | El formulario inválido no llama a `authService.login()` | `authService.login` spy configurado | 1. Dejar el formulario vacío. 2. Hacer clic en "Sign In" (o llamar `onSubmit()`). | `authService.login` no es invocado; el formulario muestra errores de validación | Evita llamadas de red innecesarias con datos incorrectos |
| TC-LoginApiError | Integración | Un error de la API muestra el mensaje de error al usuario | `authService.login` retorna `throwError(() => new Error('Invalid credentials'))` | 1. Enviar formulario con datos válidos. 2. El servicio rechaza la petición con un error. | El bloque de error es visible con el mensaje de `err.message`; `status` es `'error'` | Garantiza que los errores de autenticación llegan al usuario de forma comprensible |
| TC-LoginLoadingState | Componente | Durante la llamada al servicio el botón queda deshabilitado | `authService.login` retorna un Observable que no completa inmediatamente | 1. Enviar formulario válido. 2. Antes de que el Observable complete, verificar el estado del botón. | El botón submit está `disabled` e `isLoading()` retorna `true`; llamadas repetidas a `onSubmit()` son ignoradas | Protege contra envíos dobles y ofrece retroalimentación visual correcta |
| TC-LoginReturnUrl | Integración | El `returnUrl` del query param se pasa correctamente al servicio | Componente montado con `ActivatedRoute` mock con `returnUrl=/dashboard` | 1. Enviar el formulario con credenciales válidas. 2. Verificar el argumento de `authService.login`. | `authService.login` recibe el segundo argumento `'/dashboard'` | Asegura que el flujo de redirección post-login funciona correctamente tras una sesión expirada |
| TC-LoginPasswordVisibilityToggle | Componente | El icono de visibilidad alterna el tipo del campo contraseña | Componente renderizado | 1. Verificar que el campo password tiene `type="password"`. 2. Hacer clic en el icono de visibilidad. 3. Verificar el tipo del campo. | El tipo del campo cambia a `text`; el icono cambia a `visibility_off` | Valida la lógica de `showPassword` signal y la computed `passwordFieldConfig`; es funcionalidad crítica de UX |
