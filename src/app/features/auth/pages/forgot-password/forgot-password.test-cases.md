# Test Cases: ForgotPasswordComponent

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-ForgotPasswordHappyPath | E2E | Envío con email válido muestra el mensaje de éxito y oculta el formulario | Usuario en `/auth/forgot-password` | 1. Introducir un email con formato válido. 2. Hacer clic en "Send reset link". 3. Esperar respuesta. | El bloque de éxito es visible con el mensaje de confirmación; el formulario ya no está en el DOM | Es el flujo principal; valida que el usuario recibe feedback claro tras la acción crítica |
| TC-ForgotPasswordApiError | Integración | Un error de la API muestra el mensaje de error y conserva el formulario | `authService.requestPasswordReset` retorna `throwError(() => new Error('User not found'))` | 1. Enviar formulario con email válido. 2. El servicio rechaza la petición. | El bloque de error muestra el mensaje; el formulario permanece visible; `status` es `'error'` | Garantiza que el usuario sabe que algo falló y puede reintentar |
| TC-ForgotPasswordInvalidEmailBlocked | Componente | Un email con formato incorrecto no invoca al servicio | `authService.requestPasswordReset` spy configurado | 1. Introducir un texto que no es un email (ej. `"notanemail"`). 2. Intentar enviar el formulario. | El formulario es inválido; `authService.requestPasswordReset` no es invocado | Evita llamadas de red con datos inválidos y valida que la lógica de guardado `onSubmit` funciona |
| TC-ForgotPasswordLoadingState | Componente | El botón queda deshabilitado mientras la petición está en curso | `authService.requestPasswordReset` retorna un Observable que no completa | 1. Enviar formulario válido. 2. Verificar el estado del botón antes de que complete. | `isLoading()` es `true`; el botón está `disabled` | Evita solicitudes duplicadas de restablecimiento |
