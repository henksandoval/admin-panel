# Test Cases — AppTableComponent

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-DisplayedColumnsVisible | Componente | `displayedColumns` retorna solo las columnas visibles | Config con columnas, una de ellas con `visible: false` | 1. Configurar columnas donde una tiene `visible: false`. 2. Leer `displayedColumns()`. | El array no incluye la clave de la columna oculta. | Garantiza que columnas ocultas no aparezcan en la tabla. |
| TC-DisplayedColumnsActions | Componente | `displayedColumns` agrega la columna de acciones cuando hay acciones definidas | Config con al menos una acción | 1. Proveer acciones en el config. 2. Leer `displayedColumns()`. | El array termina con `'actions'`. | Garantiza que la columna de acciones siempre sea la última. |
| TC-FormatCellValueNull | Componente | `formatCellValue` retorna cadena vacía para `null` o `undefined` | — | 1. Llamar `formatCellValue(null, col)` y `formatCellValue(undefined, col)`. | Retorna `''` en ambos casos. | Edge case: evita que `null` o `undefined` se rendericen como texto en la celda. |
| TC-FormatCellValueFormatter | Componente | `formatCellValue` usa `valueFormatter` cuando se provee | Columna con `valueFormatter` | 1. Configurar columna con un formatter personalizado. 2. Llamar `formatCellValue(valor, col)`. | Retorna el resultado del formatter, no el valor original. | Permite transformación de datos (ej. fechas, moneda) en la capa de presentación. |
| TC-VisibleActionsFilter | Componente | `visibleActions` filtra acciones usando la función `visible` | Config con acciones, una con `visible: () => false` | 1. Proveer acciones con función `visible`. 2. Leer `visibleActions(row)`. | Solo las acciones cuya función `visible` retorna `true` están incluidas. | Permite ocultar acciones condicionalmente por fila sin romper el array de config. |
| TC-RowClickEnabled | Componente | Emite `rowClick` solo cuando `clickableRows` es `true` | `config.clickableRows = true` | 1. Simular clic en una fila. 2. Verificar output `rowClick`. | El output `rowClick` emite la fila. | Happy path: el evento de fila solo debe dispararse cuando la tabla es interactiva. |
| TC-RowClickDisabled | Componente | No emite `rowClick` cuando `clickableRows` es `false` | `config.clickableRows = false` | 1. Simular clic en una fila. | El output `rowClick` no emite. | Previene la navegación o acciones accidentales en tablas no interactivas. |
| TC-ActionClickEmitAndStopPropagation | Componente | `onActionClick` emite `actionClick` y detiene la propagación del evento | — | 1. Simular clic en una acción. 2. Verificar output y propagación. | `actionClick` emite con la acción y la fila. El evento no se propaga al row click. | Evita que el clic en una acción de fila dispare también el evento de fila. |
| TC-EmptyMessageDefault | Componente | Usa `TABLE_DEFAULTS.emptyMessage` cuando no se configura uno en el config | Config sin `emptyMessage` | 1. Instanciar sin `emptyMessage` en el config. 2. Verificar el estado vacío. | El mensaje mostrado es el valor de `TABLE_DEFAULTS.emptyMessage`. | Garantiza un mensaje de estado vacío siempre presente, incluso sin config. |
| TC-EmptyMessageCustom | Componente | Usa el `emptyMessage` del config cuando se provee | Config con `emptyMessage` personalizado | 1. Setear `config.emptyMessage = 'Sin registros disponibles'`. 2. Verificar el estado vacío. | El mensaje mostrado es `'Sin registros disponibles'`. | Permite personalizar el mensaje de estado vacío por caso de uso. |
