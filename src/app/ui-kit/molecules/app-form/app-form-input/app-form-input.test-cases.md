# Test Cases — AppFormInputComponent

> **Componente de referencia.** Este spec es el modelo de calidad para el resto de los formularios del UI-Kit.

| ID del Test | Tipo | Escenario / Propósito | Precondiciones | Pasos clave | Resultado Esperado | Justificación de Valor |
|---|---|---|---|---|---|---|
| TC-InitialValue | Componente | Renderiza el valor inicial del `FormControl` en el `<input>` nativo | — | 1. Crear `FormControl('admin@empresa.com')`. 2. Setear como input. 3. Detectar cambios. | `input.value === 'admin@empresa.com'`. | Garantiza la hidratación inicial correcta del campo desde el modelo de datos. |
| TC-FormControlSync | Componente | Actualiza el `FormControl` cuando el usuario escribe en el input | — | 1. Crear `FormControl('')`. 2. Simular evento `input` con nuevo valor. | `control.value` refleja el texto escrito. | Happy path crítico: sin esta sincronización el formulario no funciona. |
| TC-ErrorDisplayTouched | Componente | Muestra el error cuando el control es inválido y ha sido tocado | `Validators.required` | 1. Llamar `control.markAsTouched()`. 2. Detectar cambios. | Existe `mat-error` con el mensaje de error. | Garantiza el feedback de validación en el flujo de UX estándar (submit o blur). |
| TC-ErrorHiddenUntouched | Componente | No muestra error cuando el control es inválido pero no tocado | `Validators.required` | 1. No tocar el control. 2. Detectar cambios. | No existe `mat-error` en el DOM. | Evita mostrar errores prematuramente antes de que el usuario interactúe. |
| TC-CustomErrorMessage | Componente | `config.errorMessages` sobreescribe el mensaje de error por defecto | `Validators.required`, control tocado | 1. Setear `config.errorMessages: { required: 'Email es requerido' }`. 2. Detectar cambios. | `mat-error` muestra `'Email es requerido'`, no el mensaje default. | Permite mensajes contextuales por campo sin cambiar la lógica de validación. |
| TC-DisabledState | Componente | Deshabilita el `<input>` nativo cuando el `FormControl` está deshabilitado | — | 1. Crear `FormControl({ value: '', disabled: true })`. 2. Detectar cambios. | `inputEl.disabled === true`. | Garantiza que campos de solo lectura no acepten entrada del usuario. |
| TC-IsRequired | Componente | `isRequired()` es `true` y el input tiene atributo `required` cuando se usa `Validators.required` | — | 1. Crear `FormControl('', Validators.required)`. 2. Detectar cambios. | `component.isRequired() === true` e `inputEl.required === true`. | Garantiza accesibilidad y semántica HTML correcta en campos obligatorios. |
| TC-ErrorOnBlurNotOnDirty | Componente | No muestra error mientras se escribe (dirty), sí lo muestra tras blur (touched) | `Validators.email` | 1. Escribir valor inválido (solo `dirty`). 2. Verificar `errorState.shouldShow`. 3. Disparar `blur`. | En dirty: `shouldShow === false`. Tras blur: `shouldShow === true`. | Edge case de UX: el error no debe interrumpir al usuario mientras escribe. |
| TC-IconClickEmit | Componente | Emite el evento al hacer clic en el icono | `config.icon` e `config.onIconClick` configurados | 1. Disparar clic en `mat-icon`. | La función `onIconClick` se llama con el `MouseEvent`. | Habilita el patrón de "mostrar/ocultar contraseña" y acciones de campo custom. |
